# Contributing to AppForge Local

Thanks for your interest in contributing.

## Before you start

- Check existing issues and pull requests to avoid duplicate work.
- For substantial changes, open an issue first to discuss the approach.
- Keep changes focused and explain the user problem they solve.
- Do not include secrets, private model files, personal data or generated credentials.

## Development expectations

- State the operating system, device and runtime versions used for testing.
- Include exact setup and reproduction steps for bug reports.
- Add or update tests when changing behavior.
- Keep local-first behavior intact; any external service dependency must be documented and optional where practical.
- Do not claim a feature, platform or build is supported unless you have tested it.

## Pull requests

A useful pull request includes:

1. A concise description of the problem and solution.
2. Screenshots or a short recording for user-interface changes, when useful.
3. Tests run and their actual results.
4. Known limitations or follow-up work.

Keep commits readable and avoid bundling unrelated changes.

## Reporting bugs

Include the AppForge Local version, environment, steps to reproduce, expected behavior and actual behavior. Remove tokens, passwords and personal information from logs before sharing them.
